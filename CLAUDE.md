# CLAUDE.md

## Project

AI form-check app, named **fitee** (formerly "Form Check"; storage keys keep the `formcheck.v1.` prefix so existing data stays). Long term: a phone app that analyzes lifting videos and adjusts the user's training program based on detected form issues. This repo is the first prototype.

**Current goal:** turn the prototype into a working app for general use: a muscle group selector, an exercise library, technique feedback for every exercise, workout programs built from the selected muscle groups, and a training log (calendar, sets, reps, weights, progress) with a coach that adapts the plan (in the spirit of MyFitnessPal, for lifting). Built in phases (see Roadmap). The original v0 goal (squat depth from a side-view video) is folded into Phase 2.

## Hard rules

- Video never leaves the device. No uploads, no analytics. Video is kept only when the user taps "Save video" after a technique check, and only on the device (IndexedDB); otherwise the in-memory recording is discarded when the results close. (Changed at the user's request: originally no video storage at all.)
- Must run in mobile Safari and Chrome over HTTPS (needed for camera access).
- No third-party network requests. `src/privacy.ts` (imported first in `main.tsx`) blocks any cross-origin fetch/XHR/beacon, and `index.html` sets a CSP with `connect-src 'self'`. Keep both: MediaPipe tasks-vision has a built-in usage logger that POSTs to `odml.pa.googleapis.com` and can't be turned off.
- No backend and no accounts (the user chose "no login for now"). Only settings, programs, the profile, numbers (landmarks, results) and user-saved set videos are stored, and only on the device (localStorage; IndexedDB for calibration recordings, saved-set replays and videos). Exports are files saved on the device, never uploads.
- The Terms of service and Privacy policy (`src/screens/Legal.tsx`) must describe what the code actually does. Change them (and bump `TERMS_VERSION` in `src/profile.ts` so people re-accept) whenever data handling changes. They are drafts for a prototype: have a lawyer review them before a public launch.
- Keep the live skeleton overlay working.
- UI copy calls this "technique feedback". No injury-prevention or medical claims.
- Don't add checks the landmarks can't support (e.g. no spine rounding: there are no spine landmarks). When confidence is low or the camera view can't show a check, report "couldn't judge"; never guess.
- Don't download or scrape videos from YouTube, Instagram, TikTok or any other site.

## Stack

- Vite + TypeScript + Preact, no backend
- Vitest for tests (landmark JSON fixtures, no video). `tests/tsconfig.json` adds Node types for tests only.
- MediaPipe Pose Landmarker (tasks-vision, web), running on-device
- Deploy to GitHub Pages

## Roadmap

1. **Phase 1 (done):** muscle group selector, exercise library (data file), rule-based program builder, programs saved on device.
2. **Phase 2 (done):** generic form analysis engine driven by exercise config: rep segmentation, all check types, per-rep pass/fail/couldn't judge, generalized setup check, limb-proportion personalization, live recording (hands-free) and video-file analysis, results screen.
3. **Phase 3 (done):** sourced technique standards → thresholds (cited in `src/data/sources.ts` and next to each check, all still "unvalidated"). Full analysis for back squat, bench press, deadlift, overhead press, barbell row, Romanian deadlift; others "basic analysis" (placement, rep counting, range of motion).
4. **Phase 4 (done):** hidden calibration screen: label own reps, compare verdicts, tune thresholds, export thresholds JSON and landmark fixtures. Shipped together with: front/back camera flip, page transitions and motion, and the training log + coach (most of Phase 5).
5. **Phase 5 (done):** technique checks saved as numbers to the log; repeated faults lower load and add the corrective; consistent form progresses load (form gate on full-analysis lifts); technique trend per exercise; log editing (past days, edit finished workouts, notes); easier-week and behind-plan coach rules. Still open (needs real data from the user): tune the coach rules on real logs, and calibrate thresholds with real labelled reps (`src/data/calibrated.json` is empty until then).

After each phase: open a PR, wait for the user's "merge it", then confirm the Pages deploy.

## Original v0 features (now covered by Phase 2)

1. **Setup check:** show the squat placement criteria (side-on, phone around hip height, 1x lens), then run a live check on the camera preview. Whole body in frame (nose to ankles detected with good confidence) and side-on (left and right shoulders and hips nearly overlap horizontally). Show nudges like "step back" or "turn side-on". Enable recording only when the check passes.
2. **Record** a set, or pick an existing video.
3. **Detect reps** from the hip's vertical movement. At the bottom of each rep, compare hip and knee landmark heights: depth is hit when the hip is at or below the knee, with a margin the user can tune.
4. **Results:** hit or miss per rep, the bottom frame with a skeleton overlay, and "couldn't judge" when landmarks are low-confidence.

**Out of scope:** accounts, payments.

## Decisions

- Library covers free weights, bodyweight, cables and machines. Free weights are preferred by the program builder because machines can hide joints from the camera.
- Every exercise needs: at least one fault with a cue and a corrective that is another library exercise; every check links to a listed fault; checks only use declared landmarks; symmetry checks only on front-view placements; "basic" exercises only carry range-of-motion or hold-alignment checks. `tests/library.test.ts` enforces this.
- Rep tracking uses a joint's vertical movement only, so mainly-horizontal movements (cable flys, face pulls, seated cable rows) are not in the library yet.
- "Top"/"bottom" of a rep = where the tracked joint is highest/lowest on screen. Distances in checks are fractions of torso length.
- Equipment settings: full gym (everything); dumbbells only = dumbbells + bodyweight + pull-up bar (no bench); bodyweight = bodyweight + pull-up bar. A pull-up bar is always assumed.
- Program builder: weekly sets 10/14/18 by level, each muscle 2× a week (3× with 5+ days), session caps, multi-joint first, secondary muscles count half. Unloaded bodyweight moves get higher rep ranges. `minLevel`/`maxLevel` keep advanced moves from beginners and regressions (knee push-ups) from experienced lifters. Deterministic: same inputs give the same program. It adds notes when volume is scaled down or a muscle can't be trained.
- Thresholds (Phase 3): every check has a `source` (enforced by tests). Full-analysis lifts use written standards: NSCA lifting proficiencies, IPF Technical Rules 2026, Larsen et al. 2021 (squat torso angle), Duffey & Challis 2005 (bench bar path, lowering time), ACSM 2009 (tempo), Schellenberg et al. 2013 (deadlift hip range), Soucie et al. 2011 (normal joint ranges). Where a standard is qualitative only, the comment and source say the number is derived. Lockout = 165° (180° minus a 15° tolerance for 2D landmark error, Wade et al. 2023). Tempo limits are in measured seconds (engine trims the slow ends, so ACSM's 1 s → 0.8 s). Basic-analysis range checks carry a "draft, no published standard yet" source with normal joint ranges for context. Every threshold stays `status: 'unvalidated'` until Phase 4 calibration.
- Standards changes in Phase 3: squat depth = thighs parallel (NSCA; IPF is stricter, users can raise the margin), torso lean ≤ 60°, squat hip-path check removed (no standard); bench depth = elbows to shoulder level (IPF 2026 rule) instead of an elbow angle; deadlift set-up = hips below shoulders (NSCA) instead of a torso angle; row torso ≥ 60° from vertical (NSCA "slightly above parallel").
- The exercise page shows "Full analysis"/"Basic analysis" and a "How we judge it" list with each check's target and source.
- Engine: no exercise-specific code. Joint names resolve to the near side (side view, chosen by visibility) or both sides/midpoint (front view). Torso length (shoulder to hip) is the scale for distances. Reps = home → far → home turning points of the tracked joint (hysteresis = max(minAmplitude/2, 25% of movement range); reps smaller than `minAmplitude` are ignored; recordings that start or end mid-rep don't count that rep). `firstPhase` says whether the first move is eccentric or concentric (for tempo).
- "Couldn't judge" whenever a check's joints are below visibility 0.6 at the key frames, under 60% coverage for whole-rep checks, or the camera angle is wrong for the rep (side-on ratio of shoulder/hip separation to torso length < 0.35, front > 0.3; setup check is stricter: < 0.25 / > 0.4). Tempo only needs the tracked joint, so it's still judged.
- Personalization: `ProportionMeter` measures thigh/shin/upper arm/forearm ÷ torso while standing side-on during setup (saved on device, numbers only). Rules are named in config (`personalize: 'squatTorsoLean'`), based on Winter (2009) reference proportions and a bar-over-mid-foot model, capped at ±12°.
- Recording: the live camera computes landmarks as it goes and records the video to memory (see Saved sets). Hands-free mode (default on) starts 3 s after the setup check holds and stops when the lifter stays still at the start position for 3 s after a rep, leaves the frame for 2 s, or after 3 minutes. Picked video files are read locally via an object URL at 20 fps, then released.
- Results pictures: small JPEGs of each rep's turnaround frame kept in memory only and cleared when the results screen closes. Live recordings capture them at the online turning points; files seek back to the exact frames after analysis.
- User-tuned depth margin (results screen, under "Adjust depth strictness") is stored as a threshold override in localStorage.
- Exercises tab filters: muscle row plus a Filters sheet (equipment groups match if the exercise uses any selected item; "Bodyweight" = needs no weights, pull-up/dip bars and benches allowed; difficulty = the exercise's `minLevel`; compound/isolation; full analysis only). Remembered per device in localStorage.
- Design language: **heat** (the user's two brand sheets, replacing the earlier four-colour fitee look). Two themes: **Paper** (light: page `#F4ECE2`, cards Paper `#FFF9F4`, warm Ink `#1E1412` text) and **Molten** (dark: page `#151619`, cards `#222428`, Black oxide `#1B1D20`, Chrome `#D9DDE1` text, bronze `#B08D57` collars). Settings → Appearance: Automatic (follows the phone, default), Light or Dark. The logo is four plates side by side (amber, orange, flame, red) between two collars on a bar; the hero wordmark colours each letter from amber to oxblood (light) or crimson (dark). Plates per theme: light amber `#F2A21A`, orange `#EC7518`, flame `#DD4A1B`, plate red `#B5241D`, oxblood `#7A1A16`; dark amber `#F7B23B`, orange `#F48A32`, flame `#EF6235`, plate red `#E5443A`, crimson `#C9303D`. Meaning: flame is the one accent (selection, done sets, trained days, the coach, links in a darker tone); the hot gradient fills the main action buttons, ticked sets, done days and picked muscle tiles; muscle icons highlight the group in flame (no per-group colours any more). Status keeps its own colours so faults don't blur into the brand: green = clean / passed, amber = warning or couldn't judge, deep red = fault or delete. Text on fills passes WCAG AA: white on the light theme's deep flame `#C43B17` and button gradient, Black oxide on the dark theme's flame and gradient; picked tiles use 19px ExtraBold labels (large text). Type: Bricolage Grotesque self-hosted from `@fontsource-variable/bricolage-grotesque` (bundled by Vite, no font CDN; OFL licence in `THIRD_PARTY_NOTICES.md`), ExtraBold for headings and big numbers, regular for text, 600 for buttons and labels. Shapes: buttons and tiles are plate-rounded (16–22px), chips and search are pills. "Log a workout" in My workouts is a molten panel (dark with a flame glow) in both themes so self-logging stands out. The camera view and replays stay black in both themes; the skeleton is drawn in amber, low-confidence joints in red, result rings green (passed) / red (fault). How-to demos draw the figure in the text colour with flame plates.
- UI: keep it simple. Three tabs (Train, Log, Exercises); one primary action per screen; plan creation is two steps with large tappable tiles; details (weekly volume, all checks, depth tuning) go behind `<details>`. Icons are inline SVG (no icon fonts or external assets). The pose-model picker only appears on the camera test page (default: full model).
- How-to demos are animated figures, not videos (user's choice): drawn from the same camera angle as the exercise's placement, correct form by construction, no copyright or network requests, respects reduced motion (start and turnaround side by side). Demos must pass their own exercise's checks (tests/demo.test.ts); when thresholds change in Phase 3/4, fix the demo or the threshold, whichever is wrong.
- Demo figure (user's request: "human-like with muscle groups", showing "how and how much the muscle groups are being engaged" in the design language): a human body drawn from the skeleton with the ten muscle groups visible at rest in the muscle grey; working muscles glow on the heat ramp (grey, amber, orange, flame, red) by their level at that moment of the rep. The ramp has a glow stop half way to amber (`--heat-glow`): on dark a copper ember, so faint work glows warm rather than olive while amber and orange stay distinct. Chosen from a judged contest of two prototypes (athletic silhouette over an anatomy chart whose fibre lines broke the heat into stripes). One-sided exercises (one-arm row, single-leg moves, side-lying abduction, concentration curl, kickback, cable lateral raise) light only the working side's limbs (the other side rests; `Demo.otherSide` gives it a share where it helps, e.g. the back leg of a lunge). Rules (`src/demo/engagement.ts`): main movers follow the exercise's demand curve through the three profile points (start, middle, turnaround; 1 = the hardest position), at 80% while lowering (eccentric activation is lower for the same load; exercises built around the lowering, the Nordic curl and negative pull-up, set `lowering: 1`); assisting muscles the same at their lower peak; stabilisers stay near-steady (70% of their peak plus 30% following the demand); with the load resting at the start (deadlift) everything stays near rest until it leaves the floor; holds swell gently. Peak ranges: main 0.85–1, assist 0.45–0.7, steadies 0.25–0.5. The legend lists the muscles (main first), what each does, and a live bar; it says it's a guide to typical muscle use, not a measurement. No injury or medical claims.
- Demo contact: bodies rest on surfaces (BODY thickness), never sink into the floor, benches, boxes or walls; planted feet don't slide (`npm run demo:contact`). Barbell plates are drawn behind the lifter so they never cover the body; held props sit in the hand (`Side.hand`). The spine bends only where the real movement rounds or arches it on purpose (crunches); lifts like the deadlift, squat and row keep it neutral.
- Front-view one-sided exercises (e.g. side-lying hip abduction, cable lateral raise) read angles from the working side (the side whose tracked joint travels further) instead of averaging both sides.
- Calibration (Phase 4): labels are per rep (fault ids; empty = good). A check is expected to fail exactly when its fault is labelled; accuracy = agreement on judged reps ("couldn't judge" is not counted). Suggestions sweep the threshold and only appear when they beat the current agreement. Personalization is off while calibrating so thresholds suit average proportions. Recordings (landmark numbers only) live in IndexedDB, can be exported as fixtures, and are wiped by "Delete all my data". Workflow: export thresholds JSON → merge into `src/data/calibrated.json` → commit; "Use these thresholds on this phone" saves them as local overrides instead.
- Camera: the front camera is the default (users need to see the screen to set up), mirrored in the preview; a flip button sits on the preview during setup and countdown, and the choice is remembered. The back camera gives sharper landmarks when someone else films.
- Motion: page changes use the View Transitions API (slide forward/back by route depth, fade between tabs; fallback CSS entrance where unsupported), tab pill glides, cards and rows rise in with a stagger, press feedback on tappables, toasts, counting numbers, the chart line draws in. Everything collapses to instant under `prefers-reduced-motion`. Animate only transform/opacity where possible.
- Training log: weights stored in kg and shown in kg or lb (Settings). A workout from a plan day is pre-filled with the coach's weights and reps; typing a value carries it to later unfilled sets; ticking a set fills planned values and starts a rest timer. Unticked sets are dropped when finishing. Estimated one-rep max = Epley (1985). Backup is a JSON file saved on the device (all `formcheck.v1.*` keys, `app: 'fitee'`); restore reads it back and also accepts older `form-check` backups.
- Coach ("AI analysis"): rule-based and on-device, not an AI service (hard rules: no network, no backend). Double progression: same weight until every set hits the top of the rep range, then add the smallest sensible step (kg: 2 dumbbell / 5 lower-body compound / 2.5 other; lb: 5 / 10 / 5), capped at 10% (ACSM 2009: 2–10%). Two sessions below the range → about 10% lighter. A fault in 2 of the last 3 technique checks → about 10% lighter, the fault's cue, and its corrective added to the workout and offered for the plan. Insights: new bests (grouped, last 7 days), stalls (no e1RM gain in 3 sessions), week progress, muscles not trained in 10 days. Next plan day = the one after the last day trained from that plan.
- Two ways to train, chosen with the switch at the top of the Train tab (remembered; default Personal trainer): **Personal trainer** (the app builds the plan and the coach adjusts weights) and **My workouts** (you log your own: empty workout, routines you save, repeat a recent workout). Both share the log, calendar, progress and technique checks. Workouts you build yourself are named after the one or two muscle groups with the most sets ("Back & Chest"). Routines store exercises and set counts only; starting one pre-fills last time's numbers for each exercise. Any finished workout can be repeated or saved as a routine.
- Bodyweight exercises (equipment only bodyweight / pull-up bar / dip bars / bench, `isBodyweight` in `src/data/filters.ts`) log body weight plus optional added weight: the weight column becomes "+kg" (empty = body weight only) and sets are stored with `bw: true` and `weight` = added kg. Your body weight (optional, Settings) is saved with each workout that has bodyweight sets; load = body weight + added, used for volume and estimated max only when known. Without it, bodyweight progress charts most reps (holds chart the longest hold). Coach: bodyweight moves start at body weight, progress by reps until the top of the range, then by added weight in plain steps (2.5 kg / 5 lb, no 10% cap since the body is most of the load); bodyweight-only records compare reps or hold time.
- Your own exercises (`CustomExercise`): created from the exercise picker ("Create your own exercise", or "Add “…” as your own exercise" when a search finds nothing). Name and load type are required: **Bodyweight** (logged as BW + added weight, like library bodyweight moves) or **Added weight** (weight × reps); main muscles are optional (they count toward weekly sets and workout names). Names can't repeat a library or own exercise (case-insensitive; offers "Use it"). Edit from the pencil in the picker; removing only hides it (archived) so old workouts keep the name. They have no demo or technique check (no "Check technique" link), work in routines, progress and records, and are included in backups.
- Renaming: routines from the pencil on each My routines row or the routine editor's title; workouts in progress and finished workouts from the pencil next to the title (`Screen` `titleAction`).
- Form gate (Phase 5, "consistent form progresses load"): on full-analysis lifts, when every set reached the top of the range the coach adds weight only if the latest technique check in the last 21 days had at least 80% clean reps (reps with no failed check; "couldn't judge" doesn't count against). No recent check → kind `check`: same weight, "check form first", and the workout card links to the technique check; a clean check during that workout shows "Use {next weight}" which moves the unfinished sets up. Latest check with faults → same weight until a clean check. Basic-analysis, bodyweight-only and your own exercises aren't gated. Repeated faults (2 of the last 3 checks) still lower the load and add the corrective.
- Technique trend: the progress page shows clean reps per check (%, chart with a 0–100 axis), the form gate status for full-analysis lifts, and the most common fault with its cue and corrective.
- Easier week: offered when two or more plan lifts stalled (no e1RM gain in three sessions) and no easier week started in the last 28 days; one tap turns it on for 7 days: plan days get about half the sets (rounded, at least 1) and about 10% less weight; the coach shows it with "End it now". Bell et al. 2023 (Delphi consensus, Sports Med Open 9:87) is cited for what a deload is; the amounts are the app's choice. After a recent easier week, further stalls get one grouped note instead.
- Behind plan (replaces "muscles not trained in 10 days"): once you've trained for two weeks, groups with under half of their planned sets over the last 14 days (plan weekly sets × 2, secondary half, same counting as the builder) get one note; when every group is behind it says what share of the plan you did instead.
- Log editing: any finished workout can be edited (date, start time, minutes, exercises, sets, name, notes); workouts can be logged afterwards from the Log tab ("Log a past workout", or "Log a workout for this day" on a selected past day; future days can't be logged). In the editor, typing a value ticks the set; unticked sets are dropped on save. Notes are free text on any workout (shown on the workout page). "Last time" in the editor only looks at workouts before that date.
- Weekly body map (Train tab "This week" card, compact with the list behind "Sets per muscle"; Log tab card with week-by-week arrows): sets per group this week (Monday to Sunday), secondary muscles half, same counting as the builder. Target = the plan's weekly target for the group (Personal trainer mode / Log tab when you have a plan; `program.targets`), otherwise the plan level's target, and 10 sets a week without a plan (My workouts mode; the builder's beginner target). Colour: one colour family only (user's choice: no colour per muscle group), now a heat ramp: untrained grey, then any training starts at amber (30% strength so one set shows) and gets hotter through orange and flame to red at the target or more (`heatColour` / `heatAt` in `BodyHeatmap.tsx`, CSS `color-mix` between theme variables, tested in `tests/heatmap.test.ts`); a gradient legend "Not trained → Weekly target", and the list with bars, so colour isn't the only cue. Non-training muscles use a separate neutral tone. Levels (0 not trained, 1 under a third, 2 under two thirds, 3 under the target, 4 target met) are only used for the words in the tap detail ("nearly there").
- Accounts: none (user's choice, "no login for now"). First launch (or a new `TERMS_VERSION`) shows the Welcome screen until the terms are accepted ("Set up my profile" or "Skip for now"); terms and privacy pages are readable before accepting. The profile is optional and on-device only.
- Sex and age adjustments (sources in the builder header): plans are the same for everyone except: women get about 20% shorter rest (min 60 s) because they recover faster between sets (Grgic & Schoenfeld 2019; Roberts et al. 2020 for otherwise-equal programming; no menstrual-cycle changes, Colenso-Semple et al. 2023); under 18 and 65+ get no sets below 8 reps (Lloyd et al. 2014; Fragala et al. 2019 NSCA) with a note. Height is stored but not used for programming (no evidence it should be). "Prefer not to say" uses the general guidance. Sex and age are saved in the plan's inputs, so rebuilding is needed after profile changes.
- Body drawings: male and female figures from react-native-body-highlighter (MIT); the muscles are the same, the body shape differs. The profile's body drawing (default from sex, else male) is used for every icon and the body map.
- Saved sets: every analysed set (reps or hold) saves a skeleton replay (compacted landmarks + the analysis result) to IndexedDB and links it from the technique summary (`setId`); the last 60 replays without video are kept. During live recording the camera stream is recorded to memory with MediaRecorder (MP4 on iPhone, WebM elsewhere, ~1.5 Mbps, video only, no audio); picked files are kept as the file. "Save video on this phone" stores it and asks for persistent storage; otherwise it's dropped when the results close. The set page plays the video with the skeleton drawn over it (front-camera recordings mirrored as filmed), or the skeleton alone, shows the current rep and its faults, the form rating (clean-rep share: 100% Excellent, ≥80% Good, ≥50% Fair, else Needs work) and every rep's checks. Backups don't include saved sets.
- Calendar day view (Log tab, tap a day): opens a bottom sheet right over the calendar (it used to render below the body map, out of sight), with "Log a workout for this day" for past days and today. Following a link out of the sheet (a workout, a replay) reopens that day's sheet when you come back to the Log tab. The sheet shows each workout with every exercise's sets (weight × reps), notes and the form rating of that day's technique checks linked to their video or replay; checks without a workout are listed too. Days with only a technique check get an outlined dot.
- Technique checks save a numbers-only summary (reps, faults per rep, clean reps) to the log automatically; calibration recordings don't.
- Dumbbell fly has no range-of-motion check: from a side-on camera the arms move toward and away from the lens, so the shoulder angle can't be measured. Reps are still counted.

## Implementation notes

- The MediaPipe WASM runtime and pose model are served from this site (`public/mediapipe/`, populated by `npm run fetch-assets`), not from a CDN, so the app makes no third-party requests at runtime.
- `site/` holds an unrelated landing page and is not part of the app build.

## Commands

- `npm install` — installs deps and fetches MediaPipe assets (postinstall)
- `npm run dev` — dev server on all interfaces (HTTPS needed for camera on a phone; see README)
- `npm test` — run the test suite
- `npm run fixtures` — regenerate synthetic landmark fixtures
- `npm run demo:sheets -- --ids a,b --frames 5 --per 6 --out DIR` — render demos to PNG sheets (dev tool; needs Playwright)
- `npm run demo:contact` — contact report for demos (`DEMO_IDS=a,b` to narrow)
- `npm run typecheck` — typecheck app and tests
- `npm run build` — typecheck + production build to `dist/`
